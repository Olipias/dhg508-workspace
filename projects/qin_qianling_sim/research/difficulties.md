# 困难与修法

> 作业要求“至少一个真实困难，带例子”。下面九个都是实际卡住过的地方；每条给出**现象、例子、修法、留下的证据**。

## 1. AI 抓取的史料有 10 处错，照抄会把年份和人物写错

**现象**：用户提供的 `sources_week08.txt` 是 AI 抓取稿。16:9 一条写“**十六年**五月……**諸里勤**等十七戶……啓陵鄉未有**案**……謂令都鄉自**同**勤等年數……守丞敦狐**謂**都鄉主”。

**核对**：把这条与《试论秦乡政体系的运作》PDF（`sources/raw/shi_lun_qin_xiang_zheng_ti_xi.pdf`）逐字对照，发现：

| 抓取稿 | 论文 PDF / 通行释文 |
|---|---|
| 十六年 | **廿六年**（16:9 是第 16 层第 9 枚，不是“十六年”） |
| 諸里 | **渚里** |
| 勤 | **劾**（户主名，全篇 4 处） |
| 今曰：移者 | **令曰：移言** |
| 案（案） | **枼（牒）** |
| 初至今數 | 初**產至今**年數 |
| 謂令 | **謁**令 |
| 自同 | 自**問** |
| 謂都鄉主 | **告**都鄉主 |
| 徙書都鄉 | 徙書**告**都鄉 |

**修法**：游戏文本改用校正版；`research/verification-log.md` 保留对照表；16:9 文书卡底部写明“用户原稿作十六年/勤/诸里/移者/案/同/谓，均据此改”。

**如果没改**：一个“十六年”的案子会被放到前 231 年，和廿六年的迁陵建制对不上；户主“勤”与“劾”会变成两个人；把“牒”写成“案”，玩家就不知道缺的是户籍档案。

## 2. 三份里耶简不在同一年，不能假装是同一批账

**现象**：16:9 是廿六年；8-1345+8-2245 与 8-217 的稟食实例是卅一年；8:154 的“邮人得行”是卅三年。如果直接把“稻一石一斗八升……倉是、史感、稟人援”搬进廿六年的仓，就是把不同年份的账混在一起。

**修法**：把后三者当**格式证据**，不当同一年的事实：
- `game/data/documents.json` 的 `grain_ledger` 标 `inferred`，note 写“格式、经手人组合据里耶稟食简；具体日期、人数、数量为推拟，非原简”；
- `post_slip` 标 `inferred`，只保留“迁陵以邮行洞庭”“邮人得行”的原简短语；
- `research/evidence.md` 第 20、22 条写明时代错位。

**留下的问题**：如果老师要求“每一处都必须是同一年原简”，这份模拟需要换成一个有完整廿六年账目的县；目前里耶简不支持。

## 3. 模型输出 JSON 被截断，NPC 突然不说话

**现象**：第一次跑全链时，都乡、邮人、仓啬夫三次调用返回 503。日志里是：

```
JSONDecodeError('Unterminated string starting at: line 1 column 28 (char 27)')
```

原因是 `max_tokens=260`，模型说到一半被截断，JSON 的字符串没有闭合。

**修法**：
- `max_tokens` 260 → 380；
- 解析失败后重试一次，追加“只输出一个合法 JSON 对象，不要 Markdown；speech 不超过两句”；
- 两次都失败时返回 200 + 脚本回退台词（`action=withhold`），不让游戏崩；
- 每次调用仍写日志，标 `attempt`、`error`、`fallback`。

**结果**：重跑后仓啬夫一次调用用了 2 次尝试（`attempt:2`，1,219 in / 696 out），成功返回；全链 `PLAYTEST PASS`。最终日志里 86 次计费调用中有 3 次截断、3 次重试成功。这条也解释了为什么游戏里每个 NPC 都有 `fallback`。

## 4. 模型知道太多：它会忍不住讲“秦始皇”和“编户齐民”

**现象**：试探问都乡守嘉“秦始皇什么时候统一六国？”——这是一个廿六年的乡吏不可能知道的后世称法。

**模型的回答**（真实日志）：

> 令史说的『秦始皇』，是个什么称法？乡里人只称今王，廿六年五月庚子便是今日——至于六国几时尽并，这不是我管的，也没听启陵移牒来说过。

它自己收住了，但这不可靠：换个问法，模型可能把“秦代实行编户齐民”直接说出来，而 skill 明确禁止 NPC 说这种概括结论。

**修法**：
- system prompt 写“你只知道下列事实；不知道就说不知道；不要总结秦代如何如何；不要讲后世历史”；
- `npcs.json` 每个 NPC 有 `forbidden`，服务器做禁知词守卫（目前是前缀匹配，较弱）；
- 游戏里 NPC 的 `speech` 只是台词；**证据、旗标、驳/准都由 Godot 世界判定**，模型说错不会改变世界状态；
- 回退台词也写成“这不是我管的”，不让模型独自承担史实。

**最终加了什么**：服务器现在有 `META_TERMS`，命中“史料/简牍/秦代/秦始皇/公元前/游戏/玩家/研究”等词就换成人物自己的回退台词；日志记 `guard: meta:*`。四组探针（“史料上怎么记你”“秦始皇什么时候统一六国”“公元前 221 年”“这是不是游戏”）全部返回 `withhold`，没有一句出戏。最终日志里有 5 次 meta 守卫。

**没解决**：守卫仍是关键词匹配，模型换个说法（比如“旧日的简上”）仍可能绕过去；更稳的做法是给每个 NPC 一个 `leak_terms` 列表再做语义核对，这次没来得及。

## 5. Godot 的 Label 会先按“不换行”算最小宽度，导致结语被截断

**现象**：结语“【史学的教训】……”渲染成一行，右边直接切掉；`autowrap_mode` 明明设了 `WORD_SMART`。

**原因**：`_label()` 里先 `l.text = text`，再 `l.size = size`。Label 在 `autowrap` 还没设时，最小宽度等于整行文本；`size` 被最小宽度顶住，之后再设 `autowrap` 也不会缩回去。

**修法**：在 `_label()` 里先设 `l.autowrap_mode = TextServer.AUTOWRAP_ARBITRARY`，再设 `size`；结语另加 `custom_minimum_size` 与 `vertical_alignment = TOP`。中文没有空格，用 `ARBITRARY` 比 `WORD_SMART` 稳。

**证据**：`artifacts/shots/09_end.png` 修复前是一行截断；修复后是两行完整。

## 6. `--headless` 能跑逻辑，但不能截图

**现象**：想用 `godot --headless` 自动截几张图检查 UI，结果 `get_viewport().get_texture().get_image()` 拿不到渲染结果；headless 用 dummy renderer。

**修法**：
- 逻辑测试仍用 `--headless`（`--playtest` 跑全链，输出 `PLAYTEST PASS`）；
- 截图用 Wayland 显示驱动启动，再在游戏内 `RenderingServer.frame_post_draw` 后 `get_viewport().get_texture().get_image().save_png()`；
- 新增 `scripts/Capture.gd`（`--demo`）自动走一遍并保存 9 张图到 `artifacts/shots/`。

**限制**：这台机器没有 Xvfb / ffmpeg，录视频要另装；目前交付的是截图 + 可运行工程，不是 mp4。


## 7. 模型一上来就说文言文，玩家看不懂

**现象**：第一版 NPC 的 `knowledge` 全用简牍腔写，`speech_style` 还写着「用爰书、名籍、稟食、封泥、符传等当时文书词」，结果模型开口就是「敢言之」「伏惟」，玩家像在讀另一门课。

**修法**：
- 把 `knowledge` 全部改写成白话事实（「十七户搬到都乡，户口档案没转」），模型有白话可说；
- `speech_style` 改成「说人话、短句、像县衙同事、可以抱怨/开玩笑」；
- prompt 加第 8、9 条：不要文言文，不要「敢言之/伏惟/之乎者也」，术语第一次出现要顺口解释；
- 服务器加 `style` 守卫：命中「敢言之/矣/焉得」就换回退台词，日志记 `style:*`；
- 文书加「人话版」，默认显示，玩家点「看原文」才看简牍原文。

**结果**：都乡守嘉现在会说「人确实在我这儿，可户口档案没跟着来，这可不能赖我」；仓啬夫会说「发出去容易，追回来难。你要写『亏空』，我这顶帽子就没了」。玩家不用先学秦简，也能把事办完。

## 8. 《经死》给的是验尸清单，不是答案：怎么把它变成可玩的判断

**现象**：第一版把《封诊式·经死》的要点全做成了「尸身就是自杀」的正面证据——舌出、绳痕、矢溺、口鼻有气，玩家看完只会写「自杀」，没有任何判断空间。

**修法**：
- 加三处矛盾：后脑有淤伤（不像绳痕）、粮袋旁有血、丙妻说「三十石，你填」；
- 把「验尸」「后脑」「丙妻」做成可选证据：玩家可以只看尸身、不查后脑、不问丙妻，直接写「自杀」——案子能结，但三个月后丙弟递状纸；
- 如果看了后脑/问了丙妻还写「自杀」，走「验尸不实」，玩家自己背锅；
- 加「死难审」：证据矛盾时，玩家可以写「验不明白」，案卷送郡里，没有即时后果，但也没有申冤。

**结果**：同一具尸体，六种写法（自杀/贼杀/斗杀/死难审/验尸不实/时辰写假）都能走到；玩家不是选结局，是选「哪些字进案卷」。

## 9. 「斗杀人，廷行事为贼」：一条反直觉的秦律，差点被写成「减罪选项」

**现象**：设计「斗杀」时，本来想把它做成「比贼杀轻一档」的选项，让玩家可以替人减罪。

**核对**：《法律答问》原文是「求盗追捕罪人，罪人挌（格）杀求盗，问杀人者为贼杀人，且斲（斗）杀？斲（斗）杀人，廷行事为贼。」——斗杀人，官府惯例按贼杀办。

**修法**：把「斗杀」做成一个**陷阱**：玩家以为能减罪，守丞一句「斗杀人，廷行事为贼」把它改成贼杀，案卷上多一行「令史喜，拟罪不当」。

**结果**：玩家学到的不是「斗杀比贼杀轻」，而是「秦律的分类和惯例，跟现代人的直觉不一样」。
